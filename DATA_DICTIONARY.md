# Dataset: `fake_accounts.csv`

## Important: this dataset is SYNTHETIC

Every row in `fake_accounts.csv` was **generated by a Python script**
(`generate_synthetic_dataset()` in `utils/preprocessing.py`). No real social media account,
person, or platform data is included.

The numbers were designed to look realistic (for example, follower counts are right-skewed and
fake accounts tend to follow many accounts but have few followers). However, the patterns are
**assumptions made by the project authors**, not measurements of a real platform.

> Scores measured on this dataset (accuracy, precision, recall, F1) do **not** represent how well
> the model would detect fake accounts in the real world.

## How it was created

| Setting | Value |
|---|---|
| Rows | 3,000 (about 59% genuine, 41% fake after label noise) |
| Random seed | 42 (re-running the generator gives the same file) |
| Label noise | 3% of labels are flipped on purpose, because real labels are never perfect |
| Generator | `python train_model.py --regenerate-dataset` |

Account types that are mixed together:

| Class | Type | Share | Description |
|---|---|---|---|
| Genuine (0) | Regular | 80% | Normal users with balanced followers/following and regular posting |
| Genuine (0) | Casual | 12% | Rare posters, sometimes no picture or bio (looks a bit like a fake account) |
| Genuine (0) | Popular | 8% | Large audience, very complete profile |
| Fake (1) | Spam bot | 45% | Young account, follows many, few followers, few posts, digit-heavy username |
| Fake (1) | Bought followers | 25% | Many followers but almost no likes or comments |
| Fake (1) | Clone | 30% | Looks fairly normal, which makes it hard to detect |

## Columns

| Column | Type | Meaning |
|---|---|---|
| `followers` | integer | Number of followers |
| `following` | integer | Number of accounts followed |
| `posts` | integer | Total number of posts |
| `account_age_days` | integer | Age of the account in days |
| `has_profile_pic` | 0 / 1 | 1 = account has a profile picture |
| `has_bio` | 0 / 1 | 1 = account has a bio |
| `username_length` | integer | Number of characters in the username |
| `username_digits` | integer | Number of digits in the username |
| `avg_likes_per_post` | decimal | Average likes on each post |
| `avg_comments_per_post` | decimal | Average comments on each post |
| `followers_following_ratio` | decimal | `(followers + 1) / (following + 1)` |
| `posts_per_day` | decimal | `posts / max(account_age_days, 1)` |
| `engagement_rate` | decimal | `(avg_likes + avg_comments) / max(followers, 1) * 100`, capped at 100 |
| `digit_ratio` | decimal | `username_digits / username_length` |
| `is_fake` | 0 / 1 | **Target.** 0 = Genuine account, 1 = Fake account |

The first ten columns are the raw inputs. The four calculated columns are stored in the CSV so you
can read them, but `train_model.py` recalculates them from the raw columns, so the model always
uses the same formulas as the web app.

## Using your own real dataset

Replace `fake_accounts.csv` with a CSV that has at least the ten raw columns and `is_fake`
(see the table above), then run `python train_model.py`. Do **not** pass `--regenerate-dataset`,
because that would overwrite your file with synthetic data.
